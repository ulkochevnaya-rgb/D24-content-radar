2. Что настроено на start.delegator24.ru сделано 13.08

  • robots.txt — открыт весь домен, указан sitemap (до 13.08 файла не было вообще)
  • sitemap.xml — два боевых лендинга: /pochemu-sam/ и /400-zadach/
  • llms.txt — карта для AI-краулеров: описание компании + оба лендинга
  • <link rel="canonical"> на обоих лендингах
  • og:image 1200×630 на обоих (трафик идет из мессенджеров)
  • Enforce HTTPS включен: http → 301 на https (до 13.08 http отдавал 200 — дубль)
  • Своя страница 404 со ссылками на воронки (вместо стандартной GitHub)
  • Мета: title, description, og:title/description/type, favicon, viewport — на месте
  • Счетчик Метрики 39533920 + noscript-пиксель на обоих лендингах
Важно знать: субдомен пока НЕ в индексе Google/Яндекса — до 13.08 у него не было ни robots, ни sitemap, и на него нет ни одной ссылки с основного сайта (страницы-сироты). Техническая база теперь готова; для индексации не хватает ссылок с delegator24.ru — они появятся на новом сайте (Тильду решено не править). Можно ускорить: добавить домен в Вебмастер/Search Console и отправить sitemap.

4. Безопасность и заголовки (для понимания, почему так)

  • chat.delegator24.ru: HSTS, CSP, X-Frame-Options DENY, nosniff, no-referrer; корень / → 302 на delegator24.ru
  • Лендинги: CSP в meta (разрешены только Метрика, UIS, шрифты), антифрейм, honeypot + серверный rate-limit на приеме заявок
  • Скрипт UIS-виджета вставляется после window.load — их сервер отдает его до 25 секунд и раньше «подвешивал» загрузку страницы. Это не баг, а осознанная отложенная загрузка
  • Cookie-плашка на всех страницах с Метрикой (требование практики РКН)
  • Персональные страницы (/r/*, /karta/<id>) — noindex + непредсказуемые адреса. Не «чинить» их появлением в sitemap

5. AI-видимость (GEO)

  • AI-краулеры (GPTBot, ClaudeBot, PerplexityBot и др.) нигде не запрещены — осознанно
  • llms.txt: на start — ручной (норм); на delegator24.ru — автогенерация Тильды с мусорным списком страниц, править не будем — уйдет с переездом
  • Известная проблема: выдача «делегатор24 отзывы» занята негативом бывших сотрудников (antijob и др.), клиентских отзовиков нет — план работ по репутации есть у Юлии (Яндекс.Бизнес, отзовики, ответы работодателя)
  • В категорийных подборках («лучшие сервисы аутсорсинга» на finuslugi, vc.ru) компании нет — план: размещения + 2-3 экспертные статьи

7. Переезд на новый сайт (решение от 13.08.2026)

Решение: новый сайт (на коде, без Тильды) и лендинги — на основном домене delegator24.ru, хостинг — свой сервер за Caddy. GitHub остается хранилищем кода и запасным зеркалом.

Почему не GitHub Pages для основного домена: он не умеет серверные 301 — а карта редиректов на ~100 адресов Тильды и старого WP обязательна, иначе теряем накопленный ссылочный вес.

  • Карта 301 уже заготовлена: 97 адресов из sitemap Тильды + известные WP-адреса, назначения проставляются по мере готовности структуры нового сайта
  • Лендинги переезжают путями (например /zadachi/, /test/) в день переключения DNS, со start — 301
  • План переключения: снизить TTL за сутки → переключить A-запись → прогнать полный аудит → Тильду держать 2-3 недели как страховку отката
  • На новом сайте закладываются: перелинковка на лендинги, единые цели Метрики, schema.org (Organization + sameAs, Service с ценой, FAQ), ручной llms.txt, чек-лист на каждую страницу

8. Чего не делать (осознанные решения)

  • Не заводить www-варианты поддоменов (www.start, www.kp) — решение от 13.08
  • Не трогать kp.delegator24.biz — рабочее КП
  • Не «чинить» noindex на /m/, /r/*, github.io-документах — он там намеренно
  • Не править Тильду — все изменения уровня сайта идут в новый сайт
  • Не отправлять тестовые заявки через формы — каждая создает реальную сделку в CRM и задачу менеджеру
